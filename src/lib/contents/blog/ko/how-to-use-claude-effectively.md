Claude를 매일 쓰는데도 "생각보다 별로인데?"라는 느낌이 든 적 있으신가요?

그 느낌, 사실 틀리지 않습니다. 다만 문제는 Claude가 아니라 사용 방법에 있을 가능성이 높습니다. Claude가 출시된 지 2년이 넘었지만 매일 쓰는 사람들 대부분이 여전히 전체 기능의 10% 정도만 활용하고 있습니다. 어렵기 때문이 아니라, 나머지 90%가 어떻게 생겼는지 아무도 알려주지 않았기 때문입니다.

이 글에서 그걸 바꿔보려 합니다.

---

## 가장 먼저 해야 할 것: 채팅 말고 프로젝트 쓰기

새 채팅을 열 때마다 Claude는 백지 상태에서 시작합니다. 내가 누군지, 무슨 일을 하는지, 어떤 스타일의 답변을 좋아하는지 아무것도 모릅니다. 매번 자기소개를 하거나, 안 하면 나와 전혀 관계없는 일반적인 답변이 돌아옵니다.

이걸 해결해주는 게 **Projects**입니다. Projects는 대화가 바뀌어도 컨텍스트가 유지되는 영구 작업공간입니다. 한 번만 설정해두면 이후 모든 대화가 내 배경을 이미 아는 상태에서 시작됩니다.

사이드바에서 Projects를 클릭해 새 프로젝트를 만들고, "업무"나 "개인" 같은 이름을 붙이세요. 이 글의 모든 설정은 이 프로젝트 안에 들어갑니다.

---

## Claude에게 나를 소개하기

프로젝트를 만들었다면 가장 먼저 해야 할 일이 있습니다. Claude에게 나를 알려주는 것입니다. 대부분 이 단계를 건너뛰고, 그래서 답변이 항상 뭔가 어긋나는 느낌이 납니다.

아래 템플릿을 프로젝트 지식 베이스에 붙여넣고 솔직하게 채워보세요. 구체적일수록 이후 모든 답변의 질이 올라갑니다.

```
제 이름은 〔이름〕입니다.
직업/역할: 〔2~3가지 실제 하는 일〕
현재 가장 중요한 목표: 〔구체적인 목표 1~3개〕
Claude 주요 활용 목적: 〔글쓰기, 조사, 분석, 코딩 등〕
배경과 지식 수준: 〔잘 아는 것, 배우는 중인 것, 잘 모르는 것〕
선호하는 답변 방식: 〔예: 간결하게/예시 포함 상세히/단계별로/글머리표 없이〕
원하지 않는 것: 〔예: 면책 조항 없이, 제 말 반복 없이, "좋은 질문이에요" 없이〕
관심 분야: 〔관심사, 업종, 특정 분야〕
```

이걸 채웠다면 아래 프롬프트로 Custom Instructions를 만들어달라고 하세요.

```
제가 알려드린 내용을 바탕으로 이 Claude 프로젝트의 Custom Instructions를 작성해주세요.

포함 내용:
- 저는 누구이고 무슨 일을 하는지
- 기본 커뮤니케이션 스타일과 포맷
- 저와 작업할 때 절대 하면 안 되는 것
- 모든 답변에서 원하는 톤
- 매 세션에 적용할 기본 동작

Claude가 읽는 규칙서처럼 2인칭으로 작성해주세요. 구체적으로, 400자 이내로.
```

출력 내용을 Project Instructions에 붙여넣으면 끝입니다. 이제 이 프로젝트의 모든 대화에서 Claude의 기본 작동 방식이 됩니다.

## Claude를 어떻게 써야 하는가

### 검색엔진처럼 쓰지 않기

대부분의 사람들이 Claude를 네이버나 구글처럼 씁니다. 질문을 입력하고 답을 기다리는 방식입니다. 이게 가장 가치가 낮은 활용법입니다.

Claude는 정보 검색 도구가 아닙니다. 생각 파트너입니다. 추론하고, 통합하고, 논쟁하고, 컨텍스트 위에 계속 쌓아 올라갑니다. 검색엔진처럼 쓰는 순간 유용함의 80%가 날아갑니다.

**❌ 이렇게 쓰지 마세요:** "프롬프트 캐싱이 뭔가요?"

**✅ 이렇게 쓰세요:** "저는 한 세션당 Claude를 약 20번 호출하는 워크플로우를 만들고 있어요. 프롬프트 캐싱이 어떻게 작동하는지 설명해주시고, 제 상황에서 실제로 비용을 줄일 수 있는지 같이 생각해볼 수 있을까요?"

두 번째 방식은 Claude에게 함께 풀어야 할 문제를 줍니다. 첫 번째는 정의를 읽어달라는 것뿐입니다.

### 시작 전에 Claude가 먼저 질문하게 하기

거의 아무도 안 쓰는데 효과가 가장 확실한 방법 중 하나입니다. 복잡한 작업을 시작하기 전에 Claude가 먼저 질문하게 하세요.

Claude가 먼저 파악하고 시작하면 결과물이 눈에 띄게 좋아집니다. 올바른 기반 위에 만들어지기 때문입니다. 이 과정 없이는 Claude가 추측으로 진행하고, 나중에 수정하는 데 더 많은 시간이 걸립니다.

```
시작하기 전에 이걸 잘 해내는 데 필요한 가장 중요한 질문 5가지를 먼저 해주세요.
제가 답한 다음에 시작해주세요.
```

## 일반 사용자들이 잘 모르는 기법들

### 내 글쓰기 스타일 복제하기

예시 없이 Claude에게 글을 써달라고 하면 Claude 자신의 스타일로 씁니다. 문법은 맞지만 톤이 완전히 다릅니다. AI가 쓴 것처럼 들리는 이유입니다.

내 글 3~5개를 주고 패턴을 분석하게 하세요. 그 다음부터는 내 스타일로 씁니다.

```
제가 쓴 글 예시 3개를 드릴게요:

〔예시 1〕
〔예시 2〕
〔예시 3〕

제 글쓰기 스타일을 자세히 분석해주세요.
문장 길이, 리듬, 단어 선택, 단락 시작과 끝 방식,
피하는 표현, 격식 수준, 제 글의 특징이 되는 패턴을 봐주세요.

이후에 글을 써달라고 할 때는 이 스타일을 정확히 따라주세요.
자신의 기본 패턴으로 돌아가지 마세요.
```

### 반대편에서 논쟁해달라고 하기

아이디어 도움을 요청하면 Claude는 보통 동의하고 살을 붙입니다. 유용할 때도 있습니다. 하지만 아이디어를 제대로 검증하는 방법은 아닙니다.

어떤 계획, 결정, 글에 진지하게 투자하기 전에 공격해달라고 하세요. 비판이 아니라 공격입니다. 이 차이가 중요합니다.

```
제 계획은 이렇습니다: 〔계획 설명〕

당신의 임무는 이것을 박살내는 겁니다.
제가 틀렸을 수 있는 모든 가정을 찾아주세요.
이게 실패할 수 있는 모든 방법을 찾아주세요.
반대 입장에서 최대한 강하게 논쟁해주세요.
정중하게 하지 마세요. 단서 달지 마세요. 그냥 공격해주세요.

그다음, 제 입장을 변호해주세요. 제가 옳다는 가장 강력한 논거를 만들어주세요.

그리고 진짜 생각을 말해주세요.
```

### Extended Thinking 켜기

대부분의 Claude 사용자가 한 번도 켜본 적 없는 기능입니다. Extended Thinking은 Claude가 바로 답을 주는 대신 단계적으로 문제를 추론한 후 답변하는 모드입니다.

간단한 작업에는 필요 없습니다. 하지만 복잡한 결정, 분석, 패턴 매칭이 아니라 진짜로 생각해줬으면 하는 질문에는 켜볼 만합니다.

메시지 보내기 전에 뇌 아이콘을 클릭하거나 프롬프트에 이렇게 추가하세요.

```
답하기 전에 이 문제를 신중하게 생각해주세요.
단계별로 문제를 풀어가고, 추론 과정을 보여주고,
불확실한 부분을 짚은 다음 결론을 알려주세요.
```

어려운 질문에서 결과물의 차이가 꽤 큽니다.

### Claude에게 프롬프트를 써달라고 하기

가장 덜 활용되는 기능 중 하나입니다. 특정 작업에 어떻게 프롬프트를 써야 할지 모르겠다면, Claude에게 써달라고 하면 됩니다.

```
Claude가 〔실제 작업 설명〕을 도와줬으면 합니다.
이 작업에 가장 적합한 프롬프트를 작성해주세요.
역할, 컨텍스트, 형식 지시사항, 결과물을 개선할 제약 조건을 포함해주세요.
작성 후 바로 그 프롬프트를 사용해주세요.
```

## 토큰 아끼고 효율 높이는 방법

### 원하는 길이를 먼저 말하기

Claude의 기본값은 자기가 적절하다고 판단하는 만큼 씁니다. 대부분 필요 이상으로 깁니다. 토큰 낭비, 읽는 시간 낭비, 불필요한 내용이 생깁니다.

시작 전에 원하는 길이를 말해두세요.

```
최대 3문장으로 답해주세요.
```
```
핵심 5가지만 글머리표로. 설명 없이.
```
```
150자 이내로 써주세요.
```

이 한 줄로 대부분 작업의 토큰 사용량을 40~60% 줄일 수 있습니다. 잃는 건 없습니다.

### 불필요한 전제 말 없애기

Claude의 답변은 기본적으로 요청하지 않은 것부터 시작합니다. "좋은 질문이에요! 설명해드릴게요." 또는 질문을 다시 요약하거나, 면책 조항이나, 마지막에 방금 한 말을 전부 요약하는 것들입니다.

요청하지 않은 것들이 토큰을 먹고 읽는 시간을 낭비합니다.

Custom Instructions에 이걸 추가하세요.

```
전제 말, 칭찬, 제 질문 재진술로 답변을 시작하지 마세요.
바로 답변으로 들어가주세요.
특별히 요청하지 않는 한 마지막에 요약을 추가하지 마세요.
주제상 꼭 필요한 경우가 아니면 면책 조항도 필요 없습니다.
```

### 주제가 바뀌면 새 채팅 열기

Claude는 대화에서 앞에 말한 모든 것의 컨텍스트를 가지고 있습니다. 긴 대화 안에서 주제를 바꾸면 이전 컨텍스트가 전부 로드된 상태로 유지됩니다. 매 답변마다 더 많은 토큰이 쓰이고, 처리가 느려지고, 이전 대화의 컨텍스트가 새 주제에 영향을 줄 수 있습니다.

관련 없는 주제로 넘어갈 때는 프로젝트 안에서 새 채팅을 시작하세요. 프로젝트 메모리는 유지되고, 불필요한 컨텍스트만 사라집니다.

## 마치며

Claude가 나보다 똑똑하거나 더 좋은 아이디어를 가진 건 아닙니다. Claude가 가진 건 무한한 인내심, 폭넓은 지식, 그리고 내가 생각해보지 않은 각도에서 문제를 바라보는 능력입니다.

Claude를 가장 잘 활용하는 사람들은 가장 좋은 질문을 하는 사람들이 아닙니다. Claude가 자신을 이해하도록 설정하고, 실제 컨텍스트를 주고, 정보 자판기가 아닌 파트너로 쓸 줄 아는 사람들입니다.

한 번 제대로 세팅하면, 일하는 방식이 달라집니다.
