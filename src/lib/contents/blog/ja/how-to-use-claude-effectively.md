Claudeを毎日使っているのに、なんとなく「思ったより使えないな」と感じたことはないだろうか。実はその感覚、ほぼ間違いなくClaudeの使い方に問題がある。ツール側ではなく、こちら側に。

Claudeが登場して2年以上が経つが、毎日使っているユーザーの多くがまだその能力の10%程度しか引き出せていないと言われている。難しいからではない。残り90%がどういうものか、誰も教えてくれなかっただけだ。

この記事ではそれを変える。設定から実際のプロンプト技法まで、Claudeを本当に使いこなすための方法を順番に解説していく。

---

## まず最初にやること：チャットではなくプロジェクトを使う

新しいチャットを開くたびに、Claudeはゼロからスタートする。あなたの名前も、仕事の内容も、どんな文体が好きかも、何も知らない状態から始まる。毎回自己紹介をするか、しなければ的外れな答えが返ってくる。

この問題を解決するのが**プロジェクト**だ。プロジェクトはセッションをまたいでコンテキストが保持される永続的なワークスペースで、一度設定すれば、その後のすべての会話がその前提知識を引き継いで始まる。

サイドバーの「Projects」からプロジェクトを作成して、「Work」や「Personal」など用途に合わせた名前をつけよう。この記事の設定はすべてこのプロジェクトの中に入れていく。

---

## 自己紹介をClaudeに読ませる

プロジェクトを作ったら、最初にやるべきことがある。自分のことをClaudeに教えることだ。ほとんどの人がこのステップを飛ばすから、答えがいつも微妙にズレた感じになる。

以下のテンプレートをプロジェクトのナレッジベースに貼り付けて、各項目を正直に埋めてほしい。具体的であるほど、すべての回答の質が上がる。

```
私の名前は〇〇です。
職業・役割：〔実際にやっていること2〜3つ〕
今取り組んでいる目標：〔具体的な目標1〜3つ〕
Claudeの主な用途：〔ライティング、調査、コーディングなど〕
知識レベル・バックグラウンド：〔得意なこと、学んでいること〕
情報の受け取り方の好み：〔簡潔に／例つきで詳しく／箇条書き不要など〕
不要なもの：〔免責事項不要、「素晴らしい質問ですね」不要など〕
興味・専門領域：〔業界、ニッチ、関心領域〕
```

これを貼ったら、次のプロンプトを使ってカスタムインストラクションを生成させる。

```
私について伝えたことをもとに、このClaudeプロジェクト用のカスタムインストラクションを書いてください。

内容には以下を含めてください：
- 私が何者で何をしているか
- デフォルトのコミュニケーションスタイルとフォーマット
- 私と作業するときに絶対にやってはいけないこと
- すべての回答で求めるトーン
- 毎回のセッションで適用してほしいデフォルトの動作

二人称で、Claudeが読む指示書として書いてください。具体的に。400字以内で。
```

出力をプロジェクトのインストラクションに貼れば設定完了だ。これがClaudeの永続的な動作モードになる。

## Claudeをどう使うべきか

### 検索エンジンとして使わない

ほとんどの人がClaudeをGoogleのように使っている。質問を入力して答えを待つ。これが最も価値の低い使い方だ。

Claudeは情報検索ツールではない。思考パートナーだ。推論し、統合し、論じ、コンテキストの上に積み上げていく。検索エンジンとして使った瞬間、その有用性は80%失われる。

**やめるべき使い方：**「プロンプトキャッシングとは何ですか？」

**正しい使い方：**「私はClaudeをセッションあたり20回呼び出すワークフローを構築しています。プロンプトキャッシングの仕組みを説明し、このコンテキストでコストを実際に削減できるかどうかを一緒に考えてください。」

2番目のプロンプトはClaudeに解くべき問題を与えている。最初のは定義を朗読させているだけだ。

### タスクを始める前に質問させる

ほぼ誰も使っていないのに、最も効果的なテクニックの一つがこれだ。複雑なタスクを始める前に、Claudeに先に質問させる。

Claudeが先に質問すると、アウトプットが劇的に良くなる。なぜなら正しい前提の上に構築されるからだ。この指示がなければ、Claudeは推測で動き、後から修正する羽目になる。

```
始める前に、これをうまくやるために必要な最も重要な質問を5つしてください。
答えてから、作業を始めてください。
```

## 知っている人が少ないテクニック

### 自分の文体をCloneする

例文なしでClaudeに文章を書かせると、Claudeは自分のスタイルで書く。文法的には正しいが、トーンがまったく違う。AIっぽく聞こえるのはそのせいだ。

自分の過去の文章を3〜5本貼り付けて、パターンを分析させよう。その後は、自分のスタイルで書くようになる。

```
私の文章のサンプルを3つ示します：

〔サンプル1〕
〔サンプル2〕
〔サンプル3〕

私のライティングスタイルを詳細に分析してください。
文の長さ、リズム、語彙の選択、段落の始め方と終わり方、
避けていること、フォーマル度、スタイルを特徴づけるパターンを見てください。

以降、何かを書くよう頼んだときは、このスタイルを正確に合わせてください。
自分のパターンをデフォルトにしないでください。
```

### 論敵として使う

アイデアの助けを求めると、Claudeはそれを膨らませ、付け加え、拡張する。同意と肉付けが返ってくる。それが役に立つこともある。しかしアイデアのストレステストにはならない。

計画、意思決定、文章を確定させる前に、攻撃させよう。批評ではなく、攻撃だ。この違いは重要だ。

```
これが私の計画です：〔計画の説明〕

あなたの仕事はこれを破壊することです。
私が立てている前提のうち、間違っている可能性があるものをすべて見つけてください。
これが失敗する可能性のあるすべての方法を見つけてください。
反対の立場をできるだけ強く論じてください。
丁寧にしないでください。留保をつけないでください。ただ攻撃してください。

その後、私の立場を弁護してください。私が正しい理由の最も強い論拠を構築してください。

そして、あなたが本当に思うことを教えてください。
```

### Extended Thinking（拡張思考）をオンにする

ほとんどのClaudeユーザーがこれを一度も使っていない。Extended Thinkingは、答えを直接出す代わりに、Claudeが段階的に問題を推論してから回答するモードだ。

単純なタスクには必要ない。しかし複雑な意思決定、分析、パターンマッチングではなく本当に考えてほしい質問には、オンにする価値がある。

メッセージを送る前に脳のアイコンをクリックするか、プロンプトにこれを追加する。

```
答える前にこれを慎重に考えてください。
問題をステップごとに考え、推論を示し、不確かな部分を特定し、
それから結論を教えてください。
```

難しい質問でのアウトプットの質の差は、かなり大きい。

### Claudeにプロンプトを書かせる

最も活用されていない使い方の一つがこれだ。特定のタスクのプロンプトの書き方がわからないなら、Claudeにプロンプトを書かせよう。

```
Claudeに〔実際のタスクの説明〕を手伝ってほしいです。
このタスクのための最良のプロンプトを書いてください。
役割、コンテキスト、フォーマット指示、アウトプットを向上させる制約を含めてください。
それからそのプロンプトをすぐに使ってください。
```

## トークンを節約して効果を上げる方法

### 出力の長さを指定する

Claudeのデフォルトは、適切だと判断した量を書くことだ。たいてい必要以上に長い。それはトークンの無駄であり、読む時間の無駄であり、ノイズだ。

始める前に欲しい長さを伝えよう。

```
最大3文で答えてください。
```
```
箇条書き5つ。説明なし。ポイントだけ。
```
```
150字以内で書いてください。
```

この一文で、ほとんどのタスクのトークン使用量を40〜60%削減できる。失う価値は何もない。

### 前置きを消す

Claudeの回答はデフォルトで、頼んでもいないものから始まる。「素晴らしい質問ですね。解説しましょう。」とか、質問を言い直すとか、免責事項とか、最後に全部を繰り返すまとめとか。

カスタムインストラクションにこれを追加しよう。

```
前置き、称賛、質問の言い直しで回答を始めないでください。
答えに直接入ってください。
特に頼まれない限り、最後にまとめを追加しないでください。
トピックが本当に必要とする場合を除き、免責事項は不要です。
```

### 話題が変わったら新しいチャットを始める

Claudeは会話の中で前に言ったことすべてのコンテキストを引き継ぐ。長いチャットの中でトピックを切り替えると、前のコンテキストがすべて読み込まれたまま。つまり毎回の回答でより多くのトークンが使われ、処理が遅くなり、以前の話題が新しいトピックに影響する。

関係のないことに移るときは、プロジェクト内で新しいチャットを始めよう。プロジェクトのメモリは保持される。不要な荷物は捨てられる。

## まとめ

ClaudeはあなたよりもAIが賢いとか、あなたより良いアイデアを持っているということではない。Claudeが持っているのは、無限の忍耐、幅広い知識、あなたが考えていない角度から問題を考える能力だ。

Claudeから最も多くを得ている人は、最高の質問をする人ではない。Claudeを自分を理解するようにセットアップし、本物のコンテキストを与え、情報を引き出す機械としてではなくパートナーとして使い方を知っている人たちだ。

一度設定すれば、作業のやり方が永続的に変わる。
