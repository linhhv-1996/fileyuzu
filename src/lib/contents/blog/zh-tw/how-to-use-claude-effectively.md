如果你每天都在用 Claude，但總覺得它「好像還好」、「沒有想像中厲害」，那這篇文章就是為你寫的。

問題通常不在工具，而在用法。Claude 上線兩年多了，但大多數人還是把它當 Google 在用——打一個問題進去，等它回答。這是最沒效率的用法，而且你只用到它能力的 10% 左右。

這篇文章要告訴你剩下的 90% 是什麼。

---

## 第一步：用 Project，不要只開聊天視窗

每次你開一個新的 Claude 對話，它就會從零開始。不知道你是誰、你做什麼工作、你喜歡什麼樣的回答風格。你要嘛花時間重新介紹自己，要嘛就收到一個感覺跟你沒什麼關係的回答。

**Projects** 解決的就是這個問題。它是一個跨對話保留脈絡的工作空間，設定一次，之後每次對話 Claude 都已經知道你的背景。

從左側欄點「Projects」建立一個，依照用途命名，比如「工作」或「個人」。接下來所有的設定都放在這裡面。

---

## 讓 Claude 先認識你

建好 Project 之後，第一件事是把自己介紹給 Claude。大多數人跳過這步，然後納悶為什麼回答總是差那麼一點。

把下面這個模板貼到 Project 的知識庫，老實填寫每個欄位。越具體，之後每一個回答的品質就越高。

```
我叫〔你的名字〕。
我的工作是〔職稱或職業〕，主要負責〔2–3 件日常工作事項〕。
目前最重要的目標：〔1–3 個具體目標〕。
我使用 Claude 主要是為了〔列出主要用途：寫作、研究、分析、寫程式等〕。
我的背景和知識程度：〔擅長什麼、正在學什麼、完全不熟什麼〕。
我喜歡的回答方式：〔例如：直接簡潔／有例子的詳細說明／逐步拆解／不要條列式〕。
不需要的東西：〔例如：不要免責聲明、不要重複我說過的話、不要「好問題！」開頭〕。
我關心的領域：〔你的興趣、產業、利基〕。
```

填好之後，用這個 prompt 請 Claude 幫你生成 Custom Instructions：

```
根據我剛才告訴你的所有資訊，幫我寫一份這個 Claude Project 的 Custom Instructions。

內容要包含：
- 我是誰、我在做什麼
- 預設的溝通風格和回答格式
- 跟我工作時絕對不能做的事
- 每個回答要有的語氣
- 每次對話都要套用的預設行為

用第二人稱寫，像是 Claude 在閱讀的規則說明。要具體，不要泛泛而談。400 字以內。
```

把輸出貼到 Project Instructions，設定就完成了。

## Claude 不是你想的那種工具

### 別把它當搜尋引擎

這是最常見的誤用。打一個問題進去，等它給答案。這讓 Claude 的價值打了八折不止。

Claude 不是查資料的工具，它是思考夥伴。它會推理、整合、辯論、在你提供的脈絡上繼續疊加。一旦你把它當搜尋引擎用，就等於浪費掉它最核心的能力。

❌ **不好的用法：**「Prompt caching 是什麼？」

✅ **好的用法：**「我在建一個每次 session 會呼叫 Claude 大約 20 次的工作流程。幫我搞清楚 prompt caching 的運作方式，以及在我這個情況下，它實際上能不能降低成本。」

第二個問法給了 Claude 一個要一起解決的問題，第一個只是讓它念定義給你聽。

### 先讓 Claude 問你問題

幾乎沒有人在用這個技巧，但它是效果最明顯的方法之一。在開始任何複雜任務之前，先讓 Claude 來問你問題。

Claude 先問清楚，輸出品質會好很多——因為是建立在正確的基礎上。少了這個步驟，Claude 只能自己猜，你就得花時間修正本來可以一次到位的東西。

```
在開始之前，先問我 5 個最重要的問題，讓你能把這件事做好。
等我回答之後，再開始。
```

## 一般人不知道的進階技巧

### 複製你的寫作風格

叫 Claude 幫你寫東西，但沒給範例的話，它會用自己的風格寫。文法沒問題，但語氣整個不對。聽起來像 AI 寫的，因為本來就是。

給它 3–5 篇你自己寫的文章，讓它分析你的寫作模式。分析完之後，它寫出來的東西才會像你寫的，不是像一個很客氣的企業助理。

```
以下是我寫作的 3 個範例：

〔範例 1〕
〔範例 2〕
〔範例 3〕

請詳細分析我的寫作風格。包含：句子長短、節奏、用詞選擇、
段落開頭和結尾的方式、我會避開什麼、正式程度，
以及任何讓我的文章有辨識度的模式。

之後每次我請你幫我寫東西，請完全照這個風格。不要回到你自己的預設模式。
```

### 把 Claude 變成你的反對者

請 Claude 幫你「想想看這個點子怎麼樣」，它通常會順著你說、幫你補充、把想法擴大。你得到的是認同和延伸。

有時候這很有用。但這不是壓力測試一個想法的方式。

在你認真投入任何計劃、決策或文章之前，叫它來攻擊你。不是批評——是攻擊。這個差別很重要。

```
這是我的計劃：〔描述你的計劃〕

你的任務是把它打爛。找出我所有可能有問題的假設。
找出所有可能失敗的地方。盡你所能地反駁。
不要客氣。不要加「但另一方面……」。就是攻擊。

攻擊完之後，幫我的立場辯護。建立最強的論據說明為什麼我是對的。

然後告訴我你真正的想法。
```

### 開啟 Extended Thinking

大多數 Claude 用戶從來沒開過這個功能。Extended Thinking 是一個讓 Claude 在給你答案之前，先一步步推理問題的模式，而不是直接輸出。

簡單的任務不需要。但遇到複雜的決策、分析、或你希望 Claude 真的去「想」而不是依靠模式配對的問題，開啟它。

在送出訊息前點大腦圖示，或在 prompt 裡加這句話：

```
在回答之前請仔細思考這個問題。
逐步推理，展示你的思考過程，指出你不確定的地方，然後給我你的結論。
```

在難題上，輸出品質的差距是很明顯的。

### 讓 Claude 幫你寫 Prompt

這是最少人在用的技巧之一。如果你不確定某個任務要怎麼下 prompt，就叫 Claude 幫你寫。

Claude 知道什麼樣的指令能讓輸出更好。讓它把這個能力用在你身上。

```
我需要 Claude 幫我〔描述你實際的任務〕。
幫我寫出這個任務的最佳 prompt。
包含角色設定、背景脈絡、格式要求，以及任何能改善輸出的限制條件。
寫完之後，立刻用那個 prompt。
```

## 省 Token、提升效率的方法

### 直接說你要多長的回答

Claude 的預設是它覺得適合的長度，通常比你需要的還長。這表示多花了 token、多花了時間讀，還有一堆不必要的內容。

在開始前直接說你要多長：

```
最多 3 句話。
```
```
給我 5 個重點，不用解釋，就列點。
```
```
150 字以內。
```

這一個指令就能讓大多數任務的 token 使用量降低 40–60%，而且你不會損失任何你真正需要的東西。

### 把廢話前言砍掉

Claude 的回答預設會從你沒有要求的東西開始。「好問題！讓我來說明一下。」或是把你的問題重述一遍，或是免責聲明，或是最後再把剛才講的全部總結一次。

你沒有要求這些，但它們在消耗 token，也在浪費你的閱讀時間。

在 Custom Instructions 加上這段：

```
不要用前言、稱讚或重述我的問題來開始回答。
直接進入答案。
除非我特別要求，否則不要在最後加總結。
除非主題真的有必要，否則不要加免責聲明。
```

### 換話題就開新的對話

Claude 會把整個對話的脈絡都帶著走。當你在一個很長的對話裡切換話題，之前所有的內容還是被載入進去——代表每次回答花更多 token、處理更慢，而且之前對話的脈絡還可能影響到新話題的回答。

換到不相關的事情時，就在 Project 裡開一個新對話。Project 的記憶留著，多餘的包袱丟掉。

## 總結

Claude 不比你聰明，也不比你更有想法。它有的是無限的耐心、廣泛的知識，以及從你沒考慮過的角度思考問題的能力。

從 Claude 身上得到最多的人，不是會問最好問題的人。是那些把它設定好讓它真正了解自己、給它真實的脈絡、知道怎麼把它當夥伴而不是自動販賣機的人。

設定一次，改變你之後的工作方式。
