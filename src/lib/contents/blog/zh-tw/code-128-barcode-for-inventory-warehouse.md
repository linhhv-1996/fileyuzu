講到商品條碼,多數人第一個想到的是超市貨架上那種 13 位數字的 EAN-13。但如果你的需求是自己的倉庫盤點、出貨核對、公司設備貼標,EAN-13 反而不是好選擇,因為它只能放 13 位純數字,而你的 SKU 編號八成長得像 `TS-BK-M-001` 這樣,有字母、有連字號。

這種「自己的系統自己掃」的場景,業界的標準答案是 **Code 128**。物流業的出貨標籤、醫院的檢體管理、工廠的物料追蹤,用的幾乎都是它。這篇說清楚為什麼,以及它跟你可能聽過的 Code 39、QR Code 差在哪。

---

## Code 128 的三個優勢

**能編的內容最完整**。Code 128 支援完整的 ASCII 字元集:大小寫英文字母、數字、連字號、斜線等符號都能編進去。你的編號規則不管怎麼設計,它都放得下,不像 EAN-13 被鎖死在純數字。

**同樣內容,條碼最短**。Code 128 對連續數字有壓縮機制,編相同的內容,它印出來的條碼寬度明顯比其他一維格式短。標籤貼紙的面積有限,條碼越緊湊,能用的貼紙尺寸選擇越多,小標籤也塞得下較長的編號。

**內建檢查碼,誤讀率低**。每個 Code 128 條碼都自帶校驗機制,掃描讀取出錯時會直接拒讀而不是讀出錯誤內容。倉庫作業一天掃幾百次,這個特性直接決定了盤點資料的可信度。

## Code 128 跟 Code 39 差在哪

查資料時你可能會看到 Code 39 這個更老牌的格式,它曾經是工業標準,一些舊系統的文件還會指定用它。兩者的差異:

- Code 39 只支援大寫字母加數字,不支援小寫和多數符號;Code 128 支援完整字元集
- 編相同內容,Code 39 印出來的條碼寬度大約是 Code 128 的兩倍,小標籤經常放不下
- Code 39 基本款沒有強制檢查碼,誤讀風險較高

## 什麼時候該用 QR Code 而不是 Code 128

一維條碼和 QR Code 不是誰取代誰,而是用途不同:

- **Code 128**:內容是一組編號,掃描後由你的系統(POS、庫存軟體、Excel)去對應出商品資訊。編號短、掃描快、雷射掃描槍直接讀,適合高頻率的作業場景
- **QR Code**:內容本身就是完整資訊,例如網址、聯絡方式、一段說明文字,掃了直接呈現,不需要後端系統對應。適合連到商品介紹頁、產品履歷、報修表單

## 常見問題

### Code 128 有長度限制嗎?

格式本身沒有硬性上限,但實務上建議控制在 20 個字元以內。編號越長條碼越寬,標籤要越大,掃描距離的容錯也越差。管理用編號真的不需要太長。

### 一般的掃描槍和手機都讀得到 Code 128 嗎?

可以。Code 128 是最通用的一維條碼格式之一,雷射掃描槍、POS 掃描器都原生支援,手機用內建相機或任何條碼掃描 App 也能讀取。

### Code 128 可以編中文嗎?

不行,一維條碼只支援 ASCII 字元。需要在條碼裡放中文商品名稱的話,改用 QR Code;不過更常見的做法是條碼只放編號,中文名稱印在條碼下方的標籤文字,人眼辨識用。

### 自用的 Code 128 編號跟別人重複會怎樣?

只要條碼只被你自己的系統掃描(自家倉庫、自己的網店後台),重複與否不影響使用。但如果商品會被別人的系統掃描,例如寄賣到別人的店面,就有撞碼風險,這種情況該考慮的是[正式申請登記的條碼](/zh-tw/blog/product-barcode-personal-use-vs-official-gs1-taiwan)。

### 商品要上架超商,可以用 Code 128 嗎?

不行。正式零售通路的商品條碼規定使用 GS1 核發的 EAN-13,Code 128 是內部管理和物流用格式。EAN-13 的結構和申請時機,[這篇有完整說明](/zh-tw/blog/ean-13-barcode-structure-check-digit-guide)。
